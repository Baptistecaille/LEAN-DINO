# lean-dino

Self-supervised encoder for Lean 4 / Mathlib, trained with DINO on **kernel-certified
views**. Phase 1 is DINO only: no energy head, no negatives, no unrolling.

## The question phase 1 answers

Do Lean-certified views beat trivial augmentations? A bidirectional Transformer maps a
declaration to a latent vector via student/teacher self-distillation, where the positive
views are generated by Lean and certified by its kernel — not by generic text
augmentation. Three ablation arms, identical compute:

```bash
bash scripts/run_ablations.sh configs/dino_v0.yaml
```

`certified − dropout_only` is the result. A run without its ablations is not a result.

See [`docs/DESIGN.md`](docs/DESIGN.md) for the frozen invariants and the reasoning
behind them — most were arrived at by fixing real bugs.

## Order of work

```bash
# 1. Extract ONE module, then measure. Do not skip this.
python scripts/measure_corpus.py --raw data/raw

# 2. Tokenizer + splits
python scripts/train_tokenizer.py --config configs/dino_v0.yaml
python scripts/build_splits.py   --config configs/dino_v0.yaml

# 3. Train + evaluate
python scripts/train_dino.py --config configs/dino_v0.yaml
python scripts/eval_all.py   --config configs/dino_v0.yaml \
                             --ckpt outputs/dino_v0_certified/last.pt

# MLM baseline (same backbone/tokenizer, compute-parity via token budget)
python scripts/train_mlm.py      --config configs/dino_v0.yaml
python scripts/eval_baseline.py  --config configs/dino_v0.yaml \
                                 --ckpt outputs/dino_v0_certified/mlm/last.pt
```

`eval_all.py` prints a gate table. If any gate fails, phase 2 is blocked.

Training on a rented GPU instead of locally? `MathEBT_Colab_Training.ipynb` runs the
same pipeline end-to-end on Colab, pulling the raw corpus from a hosted dataset instead
of requiring a local Lean toolchain.

## Gates

| Gate | Threshold | Why |
|---|---|---|
| stability | teacher entropy > 0.5, max prob < 0.95, ≥50k steps | collapse detection |
| cos_pos | ≥ 0.80 | views of one declaration must be close *in absolute terms* |
| cos_rand | ≤ 0.30 | distinct declarations must not merge |
| top10_jaccard | ≥ 0.70 | swapping a query for a certified view must not change retrieval |
| probe_top1 | ≥ 0.55 on ~15 classes | frozen-latent domain classification |
| beats_bm25 | dense Recall@10 > BM25 | the lexical bar |

The old `cos_pos ≥ 3 × cos_rand` ratio was dropped: `cos_rand` sits near 0.05 in any
non-collapsed model, so the threshold landed around 0.15 and a useless model cleared it.

## Layout

```
lean_extractor/   Lean 4 side: extraction + certified views  (start here)
src/math_ebt/
  data/           schema, view generation (3 ablation arms), dataset, splits
  models/         backbone, DINO head (bottleneck+L2+weight-norm), student/teacher, MLM baseline
  training/       loss, schedules, DINO trainer, MLM trainer
  eval/           probe, retrieval (+BM25 +RRF hybrid), invariance, gates
scripts/
  analysis/       embedding inspection: spectrum, retrieval centering, view triviality
tests/            guards for the failure modes that actually happened
docs/DESIGN.md    frozen invariants, phase discipline, Lean naming trap, order of work
```

## Notebooks

- `MathEBT_Colab_Training.ipynb` — trains DINO end-to-end on a Colab GPU.
- `MathEBT_Metrics_Dashboard.ipynb` — plots stability/collapse metrics from a run's `metrics.jsonl`.
- `MathEBT_Comprehension_Tests.ipynb` — qualitative retrieval probes against the held-out test split.
