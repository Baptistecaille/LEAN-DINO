# DESIGN.md — lean-dino

Read this file before touching anything. It contains decisions that are **frozen**
and invariants that must not be silently changed.

## What this project is

A self-supervised encoder for Lean 4 / Mathlib. A bidirectional Transformer maps a
declaration (or a proof state) to a latent vector, trained with DINO
(student/teacher self-distillation) where the **positive views are generated by Lean
and certified by its kernel**.

The scientific claim to be tested is narrow and specific:

> Kernel-certified views produce a better representation than trivial augmentations.

Everything in phase 1 exists to test that claim. An energy head (phase 2) and
inference-time energy optimization (phase 3) come later and are **out of scope until
the phase-1 gates pass**.

## Phase discipline — do not skip ahead

| Phase | Content | Status |
|---|---|---|
| 1 | DINO only + baselines (MLM, BM25) + evaluation | **implement this** |
| 2 | Energy head, energy-InfoNCE, certified negatives | design only; do not implement |
| 3 | EBT unrolling, "thinking as optimization" | out of scope |

Do not add an energy head, negatives, or second-order gradients in phase 1. If a task
seems to require them, stop and ask.

## Non-negotiable invariants

These were arrived at by fixing real bugs. Changing any of them needs an explicit
decision, not a refactor.

1. **`proof_*` is Lean SOURCE TEXT**, extracted via `declRange` — never the
   pretty-printed elaborated proof term. Elaborated terms run to thousands of tokens
   and are kernel noise. Consequence: there is no `proof_explicit` field. The
   implicit/explicit pair applies to the **type** only.

2. **The DINO head keeps its full structure**: MLP → bottleneck 256 → L2 normalize →
   weight-normalized last layer with `g` fixed at 1 and not trained. The last layer's
   gradient is cancelled during the first epoch. Removing any of these causes collapse
   around 5k–20k steps, with a loss curve that still looks healthy.

3. **Local views are genuinely local**: short contiguous fragments
   (`max_seq_len_local = 256`), not full-length masked sequences. The local→global
   prediction asymmetry is what makes DINO work.

4. **`global_view_1` is always type-only.** It is not sampled among alternatives.
   Retrieval evaluation encodes type-only, so the model must always see that regime.
   Other transformations (alpha-renaming, hypothesis permutation, explicit printing)
   apply *on top of* the two global views.

5. **`center` is a registered buffer.** If it is a free tensor it is not checkpointed,
   and resuming training silently restarts from a zero center.

6. **Three ablation runs, same compute budget**: `dropout_only`, `naive`, `certified`.
   The C − A gap is the result. A run without its ablations is not a result.

7. **Split by file, dedup by AST hash before splitting.** No view of a test
   declaration may appear in training.

## Lean naming — a trap that already caused a bug

`add_comm` is the declaration name. `Mathlib.Algebra.Group.Basic` is the **module**.
`Nat` may be the **namespace**. These are three different things and the module path
is not a prefix of the declaration name. Linear-probe labels come from the **module**
(that is what carries the mathematical domain), never from the namespace.

## Order of work

Do not implement in file order. Do this:

1. `lean_extractor/` on **one module only** (`Mathlib/Algebra/Group/Basic.lean`).
   Then run `scripts/measure_corpus.py` and report four numbers:
   type length, proof-source length, pretty-print collision rate, share of
   declarations with a valid hypothesis permutation. These decide `max_seq_len` and
   view priorities. **Do not proceed until these numbers exist.**
2. End-to-end pipeline on that small corpus — tokenizer → dataset → train → probe.
   Metrics will be bad. The goal is that the loop runs.
3. BM25 baseline (half a day, gives the bar to beat).
4. Full Mathlib extraction.
5. Main run + the three ablations.

## Style

- Type hints everywhere. `dataclass` configs, no dict-juggling.
- No new dependency without asking. Current set: torch, tokenizers, numpy, pyyaml, tqdm.
- Every metric named in `src/math_ebt/eval/gates.py` must be logged from step 0.
  Diagnosing a collapse after the fact without teacher entropy logged is impossible.
- When a design choice is not forced by this file, write the alternative you rejected
  in a comment. Future-you will want to know it was considered.
